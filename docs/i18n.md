# Internationalisation

The web app has a small, dependency-free message layer in `apps/web/src/i18n/`. Only the shell is migrated so far (command bar, dock tabs, tool rail, settings tab labels, dialog close button, chart accessibility labels); other strings are still English literals.

## Using it

```tsx
import { useT } from '../i18n';

const t = useT(); // re-renders when the locale changes
t('topbar.undoItem', { label: 'Move' }); // "Undo Move"
```

Outside React use `t(key, params?)` (reads the current locale once). `{name}` placeholders are filled from `params`; a placeholder without a parameter stays as written.

Keys are typed from the English catalog (`en.ts`): using a key that is not in `en` is a compile error. A missing translation falls back to English at run time.

## Adding a locale

1. Add `apps/web/src/i18n/<code>.ts` exporting a `Partial<Catalog>` (or a full `Catalog`) with the same keys and `{name}` placeholders as `en.ts`.
2. In `i18n/index.ts`, widen `Locale` (`'en' | '<code>'`) and add the catalog to `CATALOGS`.
3. The locale is the `locale` field of the ui store (`store/ui.ts`, persisted as `tickerglass-ui`). A settings control that sets it is not built yet; until then use `useUiStore.setState({ locale })`.
4. Extend `i18n/i18n.test.ts` with a case for the new catalog.

New shell strings: add the key to `en.ts` first, then call `t(key)`.
