# Known limitations

Every known limitation, grouped by area. Each entry: what you see, the root cause, and a status:

- **Fixed**: resolved in the limitations pass (after Phase 7), with a short note on how.
- **Planned**: the phase it lands in and the proposed solution.
- **Inherent**: comes from the data source or a deliberate design trade-off; the mitigation is listed.

Design details live in `docs/indicators.md`, `docs/drawings.md` and `docs/persistence.md`. Update this file when
an item changes status.

## Data (Yahoo / yfinance)

| What you see                                                                                          | Root cause                                                                                            | Status                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No bid/ask lines on the price scale                                                                   | Yahoo's free data has no bid/ask quotes                                                               | **Inherent**. A previous-day-close line is offered instead (Settings → Scales and lines).                                                                                                                                 |
| Intraday history is short: 1m about 7 days per request and 30 days total, 2m–90m 60 days, 1h 730 days | yfinance/Yahoo range limits per interval                                                              | **Inherent**. 1m requests are chunked into 7-day windows, and lazy loading stops at the limit. Daily and higher intervals have full history. Phase 13 replay will warn about it.                                          |
| Intervals like 3m, 4h or 2D are built on the client                                                   | Yahoo only serves 1m 2m 5m 15m 30m 60m 90m 1h 1d 5d 1wk 1mo 3mo                                       | **Inherent**. The resampling feed builds them from the nearest lower native interval in the exchange timezone and session, so they inherit that interval's history limit.                                                 |
| Occasional failures or empty responses; news falls back to search results                             | Unofficial API: `get_news` 404s, rate limits, and the live relay relies on yfinance private internals | **Inherent**. One adapter (`providers/yahoo`) with retries, backoff, a rate limiter, a pinned version, and a polling fallback for live data. Error states get UI in Phase 15.                                             |
| Quotes show no currency until the symbol has been opened once                                         | `/api/quotes` only knows the currency after a bars/symbol request has cached it                       | **Inherent** (upstream). The app reads currency from `/api/symbols/{s}`.                                                                                                                                                  |
| Some exchanges' prices are delayed                                                                    | Yahoo's free feed delays some exchanges                                                               | **Inherent**. Nothing to do on our side.                                                                                                                                                                                  |
| Higher-timeframe indicator inputs (e.g. Pivot Points on 1W) cover at most 5000 timeframe bars         | `TF_MAX_BARS` caps the single `getBars` request in `apps/web/src/indicators/controller.ts`            | **Planned (Phase 15, performance pass)**. Page older timeframe history with `getBars({to})` when the chart's first bar is older than the series (the controller already tracks `first`/`complete`), then resend `tfBars`. |

## Indicators

| What you see                                                                                    | Root cause                                                                                                                    | Status                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| VWAP sessions/weeks/months reset at UTC midnight instead of the exchange's                      | The runtime had no timezone                                                                                                   | **Fixed**. New additive `BarsEnv` (`timezone`, `session`, `intervalSeconds`) in the setup/step context, `IndicatorRuntime.setContext`, and a worker `context` message from `chart.symbolInfo` (`/api/symbols/{s}`). `calendarPeriod()` computes periods in the exchange timezone; sessions that wrap midnight (futures) start the trading day at the session open.                         |
| VWAP has no "Hide on 1D or above" and no Quarter/Year anchors                                   | Not implemented                                                                                                               | **Fixed**. `hideOnDWM` input; Quarter/Year/Decade/Century anchors added.                                                                                                                                                                                                                                                                                                                   |
| VWAP has no Earnings/Dividends/Splits anchors                                                   | Needs event data in the runtime                                                                                               | **Planned (Phase 15, events on chart)**. Pass event times (from `/api/events/{s}`) through `BarsEnv` and reset the VWAP at each event bar.                                                                                                                                                                                                                                                 |
| VWAP "Session" for 24h products follows Yahoo's `session` string                                | When Yahoo reports no or a wrong session, the period is the exchange calendar day                                             | **Inherent**. Mitigation: with the session known, overnight sessions are handled.                                                                                                                                                                                                                                                                                                          |
| OBV has no smoothing                                                                            | Not implemented                                                                                                               | **Fixed**. standard "Smoothing" group (None, SMA, SMA + Bollinger Bands, EMA, SMMA (RMA), WMA, VWMA), with golden tests.                                                                                                                                                                                                                                                                   |
| Pivot Points only offer Traditional                                                             | Scope of the core set                                                                                                         | **Planned (Phase 12)**. Add Fibonacci, Woodie, Classic, DM and Camarilla formulas as `type` options of `pivot-points`, with golden tests.                                                                                                                                                                                                                                                  |
| Multi-timeframe history shows final higher-timeframe values (lookahead)                         | Each chart bar takes the value of the timeframe bar containing it                                                             | **Fixed** (as an option). `TimeframeInputDef.waitForCloseInput` names a bool input (reference "Wait for timeframe closes"). When it is on, chart bars show the last closed timeframe bar: no lookahead and no repainting, at the cost of one bar of lag. The default for new MTF indicators should be on. Pivot Points don't need it, since their levels come from the previous bar.              |
| Every timeframe tick fully recomputes indicators that depend on an MTF instance                 | A tick re-aligned every chart bar of the last timeframe bar, which reads as a change before the last chart bar                | **Fixed** (largely). A tick now propagates only from the first chart bar whose aligned values actually changed: zero for Pivot Points and for confirmed alignment while a bar is forming. **Remaining (Planned, Phase 15)**: with final alignment, a real change still recomputes dependents fully. Proposed fix: snapshot dependents at the first chart bar of the forming timeframe bar. |
| Shapes and background colours ignore plot offsets                                               | Shape/bgcolor outputs had no `offset`                                                                                         | **Fixed**. Additive `offset` on `ShapeDef`/`BgColorDef`, resolved outputs and the engine's `StudyShapeMeta`/`StudyBgColorMeta`. Drawing and hit testing honour it.                                                                                                                                                                                                                         |
| A palette can't say "no colour" (out-of-range indices drew entry 0)                             | No sentinel index                                                                                                             | **Fixed**. `NO_COLOR` = `STUDY_COLOR_NONE` = 255 skips the bar's segment, mark, bar, fill segment or background. Other out-of-range indices still use entry 0.                                                                                                                                                                                                                             |
| A fill bounded by hidden plots can clip at the pane edges                                       | Autoscale only counted visible plots                                                                                          | **Fixed**. Hidden plots or hlines that bound a visible fill count for autoscale.                                                                                                                                                                                                                                                                                                           |
| On brick charts (Renko, Kagi, …) studies blank out for a moment after a live rebuild            | A `reset` made all study data stale until the worker recomputed                                                               | **Fixed**. On a live brick reset the engine keeps each study's values for the leading bricks that didn't change (indicators are causal, so those values are exact). Only the changed tail waits for the recompute. History prepends on brick charts still rebuild all bricks, so they blank briefly (**Inherent**: bricks depend on the first bar).                                        |
| Right after loading older history, the oldest values and Heikin Ashi studies can differ briefly | On a prepend the engine shifts the old values right until fresh data arrives; warm-up regions and recursive transforms change | **Inherent** (by design). This avoids a blank flash, and the full recompute replaces the values within one worker round trip.                                                                                                                                                                                                                                                              |
| Interval visibility could only be edited as typed numbers                                       | No slider                                                                                                                     | **Fixed**. Each unit has a two-thumb range slider next to the number inputs.                                                                                                                                                                                                                                                                                                               |

## Drawings

| What you see                                                                                       | Root cause                                  | Status                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anchors past the last bar count overnight gaps and weekends as bar slots                           | Extrapolation used plain interval steps     | **Fixed**. `AnchorTimeline.calendar` is built from the newest 2000 raw bars in the exchange timezone. It skips weekends (unless the data trades weekends) and the hours outside the trading day seen in the data. Times in a gap map to the next slot. **Remaining (Planned, Phase 15)**: exchange holidays still count as slots (fix: learn holidays from missing weekdays in daily data, or a holiday table), and extrapolation _before_ the first bar is not session-aware (it resolves once history loads). |
| Measure tools show no volume                                                                       | Tool geometry had no bar data               | **Fixed**. Additive `DrawingGeometry.bars` (`DrawingBarData`). Date range and Date & price range show "Vol" for the measured bars.                                                                                                                                                                                                                                                                                                                                                                              |
| No box (marquee) select                                                                            | Not implemented                             | **Fixed**. Shift + drag on empty chart space adds every drawing in that pane whose extent meets the box to the selection. Plain drag still pans; Esc cancels. Note: the test uses each drawing's anchor/handle bounding box (full width for horizontal lines), so a diagonal line can be picked when only its bounding box meets the marquee.                                                                                                                                                                   |
| Coordinates tab "Bar #" is wrong on brick chart types                                              | The dialog built its own time-bar timeline  | **Fixed**. New `chart.getAnchorTimeline()` (additive) returns the timeline drawings use: bricks, `endTime`, calendar.                                                                                                                                                                                                                                                                                                                                                                                           |
| Info line labels and position stat boxes can't be clicked or dragged                               | Hit tests covered only the strokes          | **Fixed**. The Info line label and the position target/stop labels and Qty/RR box are strong body hits. They're sized with the last rendered theme and canvas-measured text.                                                                                                                                                                                                                                                                                                                                    |
| Brush end handles move a single sample                                                             | `moveHandle` replaced one point             | **Fixed**. End handles stretch the stroke: samples move by the offset scaled by path length from the fixed end.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Rays and extended lines are always considered visible (no culling)                                 | `isVisible` returned true for any extension | **Fixed**. `segmentInView` clips the (extended) segment against the pane. Used by the trend line, ray, extended line and info line, and by the parallel channel (lines plus fill band).                                                                                                                                                                                                                                                                                                                         |
| Fib extension level span may differ from reference                                               | Not verified against a reliable reference   | **Planned (Phase 15 parity sweep)**. Needs verification against the common documentation or a side-by-side capture. No reliable source was available in this pass.                                                                                                                                                                                                                                                                                                                                                    |
| Position tool default risk of 25% may differ from reference                                      | Same                                        | **Planned (Phase 15 parity sweep)**. Needs verification as above.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| On a log scale the parallel channel's width was kept in price units (lines not parallel on screen) | Offset stored as a price difference         | **Fixed**. Width is a pixel offset (`channelOffsetPx`): parallel on screen, which means a constant ratio on log scales. Handle drags work in pixels too.                                                                                                                                                                                                                                                                                                                                                        |
| No global "new drawings synced to all symbols" preference                                          | Only per-drawing scope                      | **Fixed**. Left-toolbar toggle and the command `drawings.toggleSyncNew` (`useUiStore.syncNewDrawings`, persisted). Tool-created drawings start with `scope: 'all'`; clones and pastes keep their source's scope.                                                                                                                                                                                                                                                                                                |
| Undoing a pane removal could orphan drawings if the study came back on another pane                | Drawings keep `paneId`                      | **Verified mitigated**. Study panes have deterministic ids (`pane-<instanceId>`, or the source study's pane), and pane removal folds the study and drawing removal into one undo step, so undo restores both on the same pane. **Remaining (Planned, Phase 14)**: multi-chart layouts must persist pane ids per chart so restored layouts keep this guarantee.                                                                                                                                                  |
| Pasted drawings keep a pane id that doesn't exist                                                  | Paste copied `paneId` verbatim              | **Fixed**. The engine pastes such drawings on `main`, and so does the app. Prices keep their units (a drawing copied from an RSI pane lands at RSI values on the price pane); use the `at` paste option to place it.                                                                                                                                                                                                                                                                                            |
| Touch needs very precise taps                                                                      | Same 4 px tolerance as the mouse            | **Fixed**. With `pointerType: 'touch'` the stroke tolerance is 10 px and the handle reach is +8 px.                                                                                                                                                                                                                                                                                                                                                                                                             |
| Text hit areas are approximate                                                                     | Width was estimated at 0.6 em per character | **Fixed**. `approxTextWidth` measures with an offscreen canvas in the last rendered font family (cached). The estimate is only used where no canvas exists (tests).                                                                                                                                                                                                                                                                                                                                             |
| No direct test of the main-pane OHLC magnet lookup                                                 | Not tested                                  | **Fixed**. `chart-drawings.test.ts` checks the displayed-bar OHLC, including Heikin Ashi and out-of-range bars.                                                                                                                                                                                                                                                                                                                                                                                                 |
