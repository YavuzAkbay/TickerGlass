# Known limitations

Every known limitation, grouped by area. Each entry: what you see, the root cause, and a status:

- **Fixed**: resolved in the limitations pass (after Phase 7), with a short note on how.
- **Planned**: the phase it lands in and the proposed solution.
- **Inherent**: comes from the data source or a deliberate design trade-off; the mitigation is listed.

Design details live in `docs/indicators.md`, `docs/drawings.md` and `docs/persistence.md`. Update this file when
an item changes status.

## Persistence

| What you see                                                                                                                             | Root cause                                                                               | Status                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Drawings are shared by all layouts                                                                                                       | Stored globally, one row per drawing (`docs/persistence.md` §1)                          | **Planned (Phase 14, multi-chart)**: per-layout drawings with pane ids per chart.                                                                                                                                                                                                                                               |
| Unsynced drawing edits made offline in several tabs at once could lose one tab's edits                                                   | Tabs shared one pending-id list in localStorage, last writer wins                        | **Fixed**. Pending ids carry their owning tab and every tab keeps the others' entries when it writes; a closed tab's pending ids are sent by the next start. **Remaining (Inherent)**: if that tab is still open, both may send the same change; the second gets a conflict that resolves to the same content, without a toast. |
| A drawing that arrived from another tab and was edited here reported a conflict and lost the edit (or a delete never reached the server) | This tab had no revision for it and sent it as a new drawing                             | **Fixed**. Revisions are merged from other tabs' storage events (newest wins); a change to a drawing this tab never synced is based on the server's revision (fetched first), never treated as a create. Pulls and batches run one at a time and ignore rows older than a known revision.                                       |
| Indicator and chart templates can't be saved, applied or listed while the API is unreachable                                             | They are read and written directly, without an offline cache                             | **Planned (Phase 15)**. Drawing templates, settings, notes, layouts and drawings are cached and synced later.                                                                                                                                                                                                                   |
| A layout larger than 60 KB that is still saving when the tab closes reaches the server only on the next start                            | Browsers drop keepalive requests over 64 KB                                              | **Inherent** (browser limit). A localStorage recovery copy is written on hide and pushed on the next start (a copy that did land is detected, no false conflict).                                                                                                                                                               |
| Changes made in the first moment after load can be replaced by the restored layout                                                       | Restore waits for the API                                                                | **Inherent**. Mitigated: a state identical to what is shown, a new layout and a just-migrated one are not re-applied. For 1.5 s after a layout is applied, view-only changes (zoom, scroll) are treated as the chart settling and not saved until the next edit.                                                                |
| Symbol-scoped drawings without a symbol stay in this browser only                                                                        | The server rejects them (422) and a batch is all-or-nothing                              | **Inherent** (only very old or hand-edited data). The migration fills the symbol from the storage bucket; a toast reports skipped ones.                                                                                                                                                                                         |
| Importing data reloads the page                                                                                                          | Every store changes at once                                                              | **Inherent** (by design). The import shows a dry-run preview first; "Replace" empties only the kinds of data present in the file and needs a confirmation.                                                                                                                                                                      |
| "Default" can't be used as a drawing template name                                                                                       | It stores a tool's saved default style on the server                                     | **Inherent** (by design).                                                                                                                                                                                                                                                                                                       |
| Saving a template while another tab deletes the same template can fail with a server error                                               | The upsert-by-name and the delete race on the server                                     | **Planned (Phase 15)**: retry the upsert on an integrity error. Retrying the save works.                                                                                                                                                                                                                                        |
| Two tabs of a browser without Web Locks could both run the first-run import                                                              | No mutual exclusion                                                                      | **Fixed**. `navigator.locks` (`investopen-migration`) serializes it, with a localStorage lease (30 s expiry) as fallback; the marker is re-checked inside the lock and concurrent starts in one page share one run. The lease fallback is best effort (two tabs writing it in the same millisecond).                            |
| A second browser's own pre-API data was replaced by the server's                                                                         | The migration marker skipped it                                                          | **Fixed**. Legacy keys are backed up (`<key>.premigration`) on first contact in every browser. If another browser migrated first and this one has drawings or a layout the server lacks, a toast offers to import them (as a new layout plus drawings; settings and templates are left alone).                                  |
| A layout deleted on another device while open here                                                                                       | Saves get 404                                                                            | **Fixed**. One notice, saving stops, the state is kept (`investopen-layout.orphan`) and "Save as new layout" restores it. A layout created offline is saved as a new layout, never over another device's last-used one.                                                                                                         |
| Importing data could be undone by the next start                                                                                         | Autosavers, the pagehide flush and the first-run import pushed the old local state again | **Fixed**. Import saves pending changes (or stops if it can't), halts persistence, imports, keeps the migration marker, drops the local caches and reloads. Replace needs a full backup and a confirmation; out-of-order dry runs are ignored.                                                                                  |
| A note or setting the server rejects (e.g. too large) stays only in this browser                                                         | Permanent 4xx                                                                            | **Inherent**. It stays dirty (the next start keeps it instead of taking the server's copy) and is not resent until it changes. A note written here before syncing never overwrites a different server note: the saved one is shown with "Keep mine".                                                                            |
