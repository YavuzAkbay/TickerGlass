# Known limitations

Every known limitation, grouped by area. Each entry: what you see, the root cause, and a status:

- **Fixed**: resolved in the limitations pass (after Phase 7), with a short note on how.
- **Planned**: the phase it lands in and the proposed solution.
- **Inherent**: comes from the data source or a deliberate design trade-off; the mitigation is listed.

Design details live in `docs/indicators.md`, `docs/drawings.md`, `docs/persistence.md`, `docs/compare.md`, `docs/alerts.md` and `docs/replay.md`. Update this file when
an item changes status.

### User scripts

User-written JS indicators ([user-scripts.md](user-scripts.md)).

| What you see                                                                                     | Root cause                                                                                                                                                                                                                                                                                                            | Status                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scripts can't be used in alerts                                                                  | The alerts service is a Node process with no sandbox, and `checkRegistry` rejects `user:` types                                                                                                                                                                                                                       | **Planned**. Run scripts with `node:vm` in a separate process with a timeout, or with `isolated-vm`.                                                                                                                                    |
| Scripts can't use, or be used by, other indicators, and have no timeframe or other-symbol inputs | The sandbox gets only the chart's own bars; `tfBars`, `extBars` and other instances' results are not forwarded through the sandbox port                                                                                                                                                                               | **Planned**. Forward `tfBars`, `extBars` and results through the port.                                                                                                                                                                  |
| A script's outputs (hline levels, offsets, volume profile settings) can't depend on its inputs   | The main thread reads a static JSON manifest and never runs user code                                                                                                                                                                                                                                                 | **Inherent** (v1). Workaround: plot the value with `c.set` instead.                                                                                                                                                                     |
| A script's memory use is not capped                                                              | Browsers have no per-worker memory limit                                                                                                                                                                                                                                                                              | **Inherent**. Mitigated by the 8 script instances per chart and the 64 input / output caps.                                                                                                                                             |
| A slow but legitimate script on a long history can be stopped ("Stopped: no response ...")       | The watchdog terminates a sandbox that doesn't answer within 10 s (load, bars, Check) or 5 s (anything else), counted from when a message becomes the oldest unacknowledged one; idle sandboxes are pinged every 10 s and must answer within 2 s; a sandbox 500 messages or 30 s behind is stopped ("cannot keep up") | **Inherent** heuristic. Change a setting, re-save or reload to restart it.                                                                                                                                                              |
| A malicious script can keep CPU cores busy in the background, indefinitely                       | Timers and other scheduling APIs are removed, but some task sources can't be (a rejected `import()` under the CSP, `unhandledrejection` and `securitypolicyviolation` events). A loop like `busy(1 ms); import('x:').catch(spin)` answers every watchdog ping and pins one core per script instance (up to 8)         | **Inherent**, not bounded. The 2 s ping deadline only catches a single spin longer than that. Removing the indicator (or reloading the page) is the only remedy.                                                                        |
| Live values differ from reloaded values                                                          | The script keeps state outside `ta` primitives (closure variables), which a live tick can't rewind                                                                                                                                                                                                                    | **Inherent**. The editor's Check compares a full compute with live ticks and reports the first mismatch.                                                                                                                                |
| Error line numbers may be missing or off in some browsers                                        | Lines come from engine stack traces (`user-script.js:L:C`) with a probe-measured offset                                                                                                                                                                                                                               | **Inherent**. Verified in Chromium only; elsewhere errors may have no line or a wrong one.                                                                                                                                              |
| Network isolation depends on the worker's response CSP header                                    | Only the bundled nginx, `vite dev` and `vite preview` set it; the page itself has no CSP                                                                                                                                                                                                                              | **Inherent**. A custom proxy or CDN must pass `Content-Security-Policy` through for `/assets/sandbox-worker-*.js`, otherwise only the JS lockdown remains and dynamic `import()` is open. A page-wide CSP is a separate hardening item. |
| `vite dev` only: a script can make same-origin GET requests with `import('/...')`                | The dev worker's CSP keeps `script-src 'self'` because Vite serves the worker as separate same-origin modules                                                                                                                                                                                                         | **Inherent** to Vite dev module serving. The response is not readable and nothing leaves the origin; production and `vite preview` have no `'self'` and block it.                                                                       |
| No version history for scripts, and no TypeScript or standard                                        | Not built (the editor is a plain text area; one stored revision per script)                                                                                                                                                                                                                                           | **Planned** only as a possibility, not scheduled.                                                                                                                                                                                       |
